# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Двуязычный (армянский + русский) веб-тест по Конституции Республики Армения для подготовки к экзамену на гражданство. Чистый статический сайт: HTML + CSS + ванильный JS, **без сборки, без npm, без фреймворков, без бэкенда**. Открывается как обычные файлы.

## Запуск

Локальный сервер (нужен именно сервер, а не `file://`, потому что страницы подключают внешние `.js`):

```bash
python3 -m http.server 8080
# затем открыть http://localhost:8080/ («Тест на знание Конституции», 33 вопроса)
# и http://localhost:8080/full.html («Тест для подготовки», 135 вопросов)
```

Тестов/линтеров нет. Проверка — вручную в браузере (см. «Чек-лист поведения» ниже).

## Архитектура

Две страницы используют **одну общую логику и стили**, отличаясь только данными и разметкой шапки:

| Страница | Заголовок | Подключает | Банк вопросов |
|---|---|---|---|
| `index.html` | «Тест на знание Конституции Республики Армения (arlis.am)» | styles.css, articles.js, **questions-official.js**, config.js, app.js | 33 official |
| `full.html` | «Тест для подготовки» | styles.css, articles.js, **questions-full.js**, config.js, app.js | 135 = 33 official + 102 из экзаменационного набора |

Порядок подключения скриптов важен: данные (`articles.js`, `questions-*.js`) и `config.js` грузятся **до** `app.js`, который читает их через глобальные `const`.

**Контракт между файлами (всё через глобальные переменные, без модулей):**
- `articles.js` → `const ARTICLES` (карта `"номер_статьи" → русский текст`, 165 ключей по редакции Конституции РА 2015) и `const CONSTITUTION_URL`.
- `questions-official.js` / `questions-full.js` → `const ORIGINAL_QUESTIONS` (массив). Каждая страница грузит ровно один из них; имя переменной одинаковое, поэтому `app.js` не знает, какой тест запущен.
- `config.js` → `const TEST_COUNTS = { official: 33, full: 135 }` и `const LAST_UPDATED` (дата). Нужен для кросс-ссылки (промо-кнопка ведёт на *другой* тест, чьи данные на странице не загружены) и для даты в футере. Число вопросов **текущего** теста при этом всегда берётся из `ORIGINAL_QUESTIONS.length`, а не из `TEST_COUNTS`.
- `app.js` читает `ORIGINAL_QUESTIONS`, `ARTICLES`, `TEST_COUNTS`, `LAST_UPDATED`, рендерит в `#quiz`.

**Форма вопроса:**
```js
{ hy: "...", ru: "...",
  options: [ {hy,ru}, {hy,ru}, {hy,ru} ],
  correct: 0|1|2,            // индекс правильного варианта
  source: "official",        // сейчас во всём проекте единственное значение
  article: "47",             // ключ в ARTICLES; опционален
  note: "..." }              // служебная пометка происхождения; в UI не показывается
```

**Сейчас у всех вопросов на обеих страницах `source: "official"`** — поэтому бейджи источника нигде не показываются (`SHOW_BADGES=false`, см. ниже).
- `index.html` → 33 вопроса из постановления № 1040-Н (arlis.am).
- `full.html` → те же 33 official + 102 вопроса из экзаменационного набора (тоже помечены `source:"official"`, чтобы бейджи не появлялись). У этих 102 нет поля `article`.

Старых пулов `generated` (сначала 142, потом 193) и тега `"appeared"` в банке больше **нет**. Механизм `source`/бейджей сохранён на будущее: если появятся вопросы с другим значением `source`, бейджи включатся автоматически.

## Ключевые механизмы в app.js (поведение, которое нельзя ломать)

- **Два режима, независимое состояние.** `modeData.learn` и `modeData.test` — у каждого свой массив `questions` и свой `state` (answers/score/answered). Глобальные `questions`/`state` — ссылки на текущий режим.
- **Режим «Обучение»** = все вопросы в **фиксированном исходном порядке** (`buildLearnQuestions` = `ORIGINAL_QUESTIONS.slice()`, БЕЗ перетасовки — порядок не меняется при обновлении страницы; сначала 33 official, затем 102 новых). **Режим «Самопроверка»** = `TEST_QUESTION_COUNT` (33) случайных из всего банка (`buildTestQuestions` = shuffle + slice).
- **Бейджи источника автоматические:** `SHOW_BADGES = (число разных source) > 1`. Сейчас на обеих страницах все вопросы `source:"official"` → бейджей **нет нигде**. Если в банк добавят вопросы с другим `source`, бейджи включатся сами. Не хардкодить per-page.
- **Число вопросов автоматическое, не хардкодится в HTML.** Счётчик и футер текущего теста считаются из `ORIGINAL_QUESTIONS.length` (`updateProgress`, `fillFooter` + склонение `pluralVoprosy`). Число вопросов в промо-кнопке перехода на *другой* тест берётся из `TEST_COUNTS` (`fillTransitionCount`, ключ — атрибут `data-count`). В разметке `<span class="tb-count">…</span>` — плейсхолдер, заполняется из JS.
- **Верхняя навигация, дата, дисклеймер.** В шапке обеих страниц — отдельная строка-навигация (`.top-nav`) со ссылкой на курс армянского языка (открывается в новой вкладке). В футере — «Последнее обновление: …» (`fillLastUpdated` из `LAST_UPDATED`). В фиолетовом боксе (`.section-intro`) на обеих страницах — дисклеймер о неофициальности тренажёра.
- **Сохранение прогресса «Обучения» в localStorage.** Ключи неймспейсятся по тесту: `data-test` на `<body>` (`official` / `full`) → `arm-<id>-answers` (объект `ключ_вопроса → индекс_ответа`), `arm-<id>-marks` (массив ключей «на повторение»), `arm-<id>-filter`. **Ключ вопроса — хеш армянского текста** (`hashKey`, FNV-1a в base36), а не индекс: индекс сдвинулся бы при добавлении или перестановке вопросов и прогресс уехал бы на чужие вопросы. При загрузке ключи, которых нет в текущем банке, отбрасываются. Состояние обучения — производное от хранилища (`stateFromStore`), а не отдельная память. «Самопроверка» НЕ сохраняется: это разовая попытка.
- **Список «на повторение» и фильтр.** У каждой карточки — кнопка-метка `.mark-btn` (без метки «Повторить», с меткой «🔖 В повторении»): в обучении всегда, **в самопроверке — только после ответа** (до ответа она отвлекала бы от экзаменационного вида). Ошибочный ответ добавляет вопрос в список автоматически **в обоих режимах**. При этом в самопроверке НЕ показывается ничего про сам список — ни фильтра, ни действий, ни кнопок в итоговой сводке: отмеченное всплывает в «Обучении» во вкладке «Повторить». Ответы самопроверки по-прежнему не сохраняются, поэтому отмеченные там вопросы попадают в повторение неотвеченными. Над списком в `.sticky-controls` — **компактный** сегментированный фильтр `.repeat-filter` (`Все · 135` / `🔖 Повторить · N`; `inline-flex` по ширине контента — он НЕ равноценен вкладкам режимов и не должен растягиваться на всю строку), он же режим повторения: это то же обучение, только `buildLearnQuestions()` фильтрует банк по `marksStore`. Клик по метке НЕ перестраивает список (карточка не должна исчезать под пальцем) — снятая метка учтётся при следующем переключении фильтра. Строка `.repeat-actions` («Пройти заново» / «Очистить список») видна только при активном фильтре повторения, кнопки заблокированы при пустом списке.
- **Сводка в режиме повторения — без «пройден / не пройден».** Это тренировка, а не тест: `showSummary` для `learnFilter === 'repeat'` показывает «Правильно N, с ошибкой M» и кнопки «Убрать правильные из списка · N» (снимает метки с верно отвеченных) и «Пройти список заново» (стирает ответы отмеченных). Проходной балл считается только в обычной сводке.
- **Перенос прогресса между браузерами** (свёрнутый блок `.backup` под кнопкой «Заново», один и тот же на обеих страницах). Бэкенда нет, поэтому прогресс переносится текстом: `buildBackupCode()` кодирует ответы и метки в строку `AT1|<test-id>|a=<ключ>:<ответ>,…|m=<ключ>,…` (~2 КБ при полностью пройденных 135 вопросах). Кодируются **ключи-хеши**, не индексы, — код остаётся годным после пополнения банка. `parseBackupCode()` отказывает, если `test-id` не совпадает с текущей страницей (код от 33 вопросов не применится к 135), и молча пропускает ключи, которых нет в банке, сообщая их число. Импорт **заменяет** прогресс целиком, с подтверждением, если текущий не пуст. Копирование в буфер — `navigator.clipboard` с откатом на `execCommand('copy')`; отдельно есть «Скачать файлом» / «Выбрать файл» (Blob + FileReader) для случаев, когда буфер недоступен.
- **Быстрый переход к вопросу — через счётчик прогресса, отдельного контрола в шапке нет.** Счётчик `#counter` («6 / 135», пунктирное подчёркивание) — это `<button>`; тап подменяет его полем `#jumpInput` на том же месте, Enter — переход, Esc или потеря фокуса — возврат счётчика. Так в шапке не появляется ни одного лишнего элемента: предыдущие подходы (сетка из 135 квадратиков, затем форма «К вопросу [№] →» рядом с тумблером перевода) были отвергнуты как визуально навязчивые — **не возвращать их**. `findQuestionIndexByNumber()` ищет ровно тот номер, который напечатан в заголовке карточки: в режиме повторения это номер из полного списка (там пропуски), в остальных режимах — позиция. `jumpMaxNumber()` задаёт `max` и подсказку `1–N` по режиму (135 в обучении и повторении, 33 в самопроверке). Неверный номер — красная рамка поля, поле остаётся открытым; диалогов нет.
- **Возврат к месту остановки.** `scrollToResumePoint()` при входе в «Обучение» прокручивает к первому неотвеченному вопросу (мгновенно, с уточнением через `requestAnimationFrame` и `setTimeout 150` — высота карточек меняется после подгрузки шрифтов, одного прыжка не хватает). Если всё отвечено или прогресса нет — обычный скролл в начало.
- **Переключение перевода не должно дёргать страницу.** Класс `no-ru` меняет высоту всех карточек, поэтому `applyRu` идёт через `withScrollAnchor()`: перед изменением запоминается первая видимая карточка и её смещение от низа липкой шапки, после — скролл компенсируется на разницу. Абсолютный `scrollY` при этом меняется сильно (на 135 карточках — на десятки тысяч пикселей), а картинка на экране стоит на месте. Любое другое изменение, меняющее высоту списка, тоже нужно оборачивать в `withScrollAnchor`.
- **Номер вопроса в режиме повторения** — `Вопрос 2 (№ 3 в списке)`: позиция в отфильтрованном списке плюс исходный номер из `QUESTION_NUMBERS` (`originalNumberOf`), чтобы не путаться при переходах между режимами.
- **Кнопка «Заново» стирает только ответы**, метки «на повторение» переживают сброс — их чистит отдельная кнопка в строке фильтра.
- **Переключатель русского перевода в «Обучении».** Тумблер `#ruBtn` (в `.sticky-controls`, под прогрессом) вешает на `<body>` класс `no-ru`, который теми же селекторами, что и `test-mode` (`.q-ru`, `.opt-ru`, `.ru-only`), скрывает перевод. Состояние в `localStorage` (`RU_KEY = 'arm-test-ru'`, по умолчанию перевод включён). В режиме «Самопроверка» тумблер скрыт (`body.test-mode .ru-toggle { display: none }`) — там перевода нет всегда. Блок статьи (`ARTICLES`, только по-русски) переключателем НЕ скрывается: это справка, а не перевод вопроса.
- **Блок статьи** под вопросом показывается только в режиме «Обучение» и только если у вопроса есть `article` и он есть в `ARTICLES`.
- **Лоадер** при входе в режим теста показывается только когда пул «свежий» (`testPoolFresh`: при первом заходе и после «Заново»), не на каждом переключении.
- **Проходной балл** — `Math.floor(questions.length/2)+1` (для теста = 17 из 33).
- Выбор режима сохраняется в `localStorage` (`MODE_KEY = 'arm-test-mode'`).

## Правила работы с контентом

- **Армянский — источник истины для теста.** Русский (`ru`) — вспомогательный перевод, в режиме «Самопроверка» скрывается CSS-классами (`body.test-mode .q-ru/.opt-ru/.ru-only`).
- Тексты вопросов/вариантов/правильных ответов сверяются с официальным источником: постановление № 1040-Н на arlis.am (`https://arlis.am/hy/acts/122105`). Тексты статей — Конституция РА 2015 на president.am.
- При смене формулировок отвлекающих вариантов приоритет у реальных экзаменационных, а не у выдуманных.
- **Нумерация статей приведена к редакции Конституции РА 2015.** `articles.js` содержит 165 ключей; тексты под номерами исправлены, поля `article` у вопросов согласованы. В частности, у official-вопросов поправлены 4 привязки: флаг → ст. 21, столица → ст. 22, административно-территориальные единицы → ст. 121, война → ст. 118.
- Правильность привязки `article` к вопросу проверять отдельно — там встречались ошибки.

## Деплой (прод)

Прод — GitHub Pages: **https://astromech-dev.github.io/armenia-test/** (и `/full.html`). Настроен деплой прямо из ветки `main`, корень репозитория (нет отдельной ветки `gh-pages`, нет GitHub Actions, нет `docs/`). Поэтому:

```bash
git push origin main   # это и есть «залить на прод»
```

**Кеш-бастинг обязателен.** Все `<script>`/`<link>` подключаются с версией — `app.js?v=8`, `styles.css?v=8` и т.д. Без неё браузер на телефоне/планшете держит старый `app.js` неделями, и пользователь видит «ничего не изменилось». **При каждом изменении `app.js`, `styles.css` или `questions-*.js` поднимайте `?v=` в ОБОИХ html-файлах.**

После пуша Pages пересобирается автоматически, обычно за ~1 минуту (иногда до пары минут). Отдельного шага сборки нет — что в `main`, то и на проде. После обновления на телефоне/браузере может понадобиться жёсткий refresh (Cmd+Shift+R), т.к. `styles.css`/`app.js`/`questions-*.js` кешируются.
